# Stock Watcher — Service Documentation

## Overview
stock-watcher is a single-process REST API written in Go 1.24 using the Gin web framework. It listens for HTTP on the port defined by the PORT environment variable, defaulting to 8080 when PORT is unset. The service's role is to maintain an in-memory stock watchlist and serve mock price data suitable for demos, prototypes, or automated tests. It does not integrate with live market feeds, databases, or message brokers. Runtime dependencies are limited to Gin for routing and middleware, plus the standard library's slog for structured logging. The codebase is a single deployable binary from the Most-Fullstack/stock-watcher repository with no separate microservices.

## Architecture and Middleware
stock-watcher routes every request through Gin, where handlers parse paths and JSON bodies before touching shared in-memory state. Structured logging via slog records key events and request outcomes in a consistent machine-readable shape for aggregation and search. Graceful shutdown listens for termination signals, stops accepting new HTTP connections, allows existing requests to finish within a bounded window, then exits so orchestrators can replace instances without abrupt disconnects. The default design does not ship authentication or authorization middleware; if needed, operators typically terminate TLS and enforce identity at a reverse proxy or API gateway in front of stock-watcher.

## API Endpoints
stock-watcher exposes five REST operations, all over plain HTTP unless TLS is added externally. GET /health returns a lightweight liveness response for probes and uptime checks. GET /api/stocks returns the full watchlist with current mock fields for every symbol. GET /api/stocks/:symbol returns one symbol's snapshot or a not-found style response when the ticker is absent. POST /api/stocks accepts a JSON body to register a new watchlist entry, validating input and rejecting duplicates where the handler enforces uniqueness. DELETE /api/stocks/:symbol removes a symbol from the watchlist when it exists. No API keys or bearer tokens are required in the stock baseline.

## Data Models
stock-watcher represents each watchlist row with a Stock structure whose exported fields drive JSON serialization. Symbol identifies the ticker string clients use in URLs and filters. Name carries a human-readable company or instrument label. Price holds the latest mock quote as a floating value. Change and ChangePercent describe movement relative to the prior synthetic tick for quick scanning in UIs. UpdatedAt timestamps the last price refresh, while AddedAt records when the symbol joined the watchlist. Together these fields give clients enough context to render tables and sparklines without secondary lookups, and they chunk cleanly for documentation search because the names mirror common finance vocabulary.

## Business Logic
stock-watcher fabricates prices in application code instead of calling external brokers, using algorithms that produce plausible drift and percentage changes between reads. When a client POSTs a new symbol, the service seeds initial mock values before subsequent GETs may refresh them. DELETE fully removes the symbol from memory so later GETs report absence. List endpoints merge membership metadata with freshly generated quotes on each request where the implementation does so, which keeps behavior obvious for tests. Because all state lives in process memory, restarting the binary clears the watchlist unless automation repopulates it through POST calls after boot.

## Troubleshooting
stock-watcher frequently fails to start when PORT is already bound by another program; freeing the port or choosing a different PORT value fixes listen errors. An empty watchlist immediately after deploy is normal for in-memory storage—use POST in setup scripts or manual calls to seed symbols before assertions. Confusing 404 responses usually mean the path omitted /api or used the wrong HTTP method rather than a missing ticker. If structured logs seem quiet, confirm the slog level and output destination match the deployment environment. Heavy concurrent mutation is not designed for strong durability guarantees beyond what the in-memory synchronization provides.

## Environment Variables
stock-watcher honors PORT as the TCP port for the HTTP server, falling back to 8080 when PORT is missing or blank so local development and many container defaults align without extra config. Platform schedulers should inject the port their mesh or ingress expects, for example 8080 inside a pod while the service fronts another external port. No database URLs, API keys, or broker secrets are required in the baseline mock implementation, which reduces operational surface area.
